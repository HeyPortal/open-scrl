# Hosting the web app

The web app is published at <https://heyportal.github.io/open-scrl/>. It runs
entirely in the browser: the host serves the application files, while projects
and imported photos remain in the visitor's local browser storage.

## GitHub Pages

The `deploy-pages` job in `.github/workflows/ci.yml` publishes `dist/` after
all verification jobs succeed on `main`. Pull requests and manual workflow runs
on feature branches run the checks without publishing. The checks run in
parallel, including two editor shards and separate production PWA jobs at both
`/` and `/open-scrl/`. See [browser testing](testing.md) for the job structure
and diagnostic artifacts.

The deployment job installs Node 22 and the Bun version from `packageManager`,
uses `bun install --frozen-lockfile`, and builds for the base path reported by
`actions/configure-pages`. The Vite asset URLs, manifest launch URL, manifest
scope, service-worker registration, and application logo use that base path.
The bundle check runs against the same build before it is uploaded and deployed.

In the repository's **Settings → Pages**, choose **GitHub Actions** as the
publishing source. This is configured for the canonical repository. Forks need
to enable Pages in their own settings. A fork with a different repository name
still gets the deployment base path from GitHub's Pages metadata.

To publish a new version, merge a PR into `main` and let CI finish. To redeploy
without a code change, choose **Actions → CI → Run workflow** with `main`
selected. A failed verification prevents deployment. Builds and Pages artifacts
are generated by Actions and are not committed to the repository.

The workflow follows the official [GitHub Pages workflow guidance](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)
and [Vite deployment guide](https://vite.dev/guide/static-deploy.html#github-pages).

## Build for another static host

By default, `bun run build` targets `/`, suitable for an app at a domain's root.
Set `SCRL_BASE_PATH` for hosting in a directory, with leading and trailing slashes:

```bash
SCRL_BASE_PATH=/open-scrl/ bun run build
SCRL_BASE_PATH=/open-scrl/ bun run bundle:check
SCRL_BASE_PATH=/open-scrl/ bun run preview
```

Upload the contents of `dist/` to that directory and serve them over HTTPS.
Bun and Node are build tools; visitors do not need either installed.

To exercise that deployment locally, run the production tests:

```bash
SCRL_BASE_PATH=/open-scrl/ PWA_PORT=5187 bun run test:pwa
```

The test server serves only the configured path, so an accidental request to
`/assets/` or `/sw.js` cannot hide a broken deployment path. See
[Browser testing](testing.md) for reports and failure traces.

Existing project data belongs to the browser origin where it was created.
Moving to another domain does not move stored projects or photos automatically.

## Google Fonts catalog

The optional Google Fonts catalog uses a browser-visible API key. Set
`VITE_GOOGLE_FONTS_API_KEY` at build time to provide a deployment default, or let
visitors enter their own key in **Typography → Manage fonts → Google Fonts**.

For GitHub Pages, open **Settings → Environments → github-pages** in the
repository and add an environment secret named `VITE_GOOGLE_FONTS_API_KEY`.
The deployment build reads that secret; checks and pull-request builds do not.
Local `.env.local` files are ignored by Git and are not available to Actions.
After adding or changing the secret, redeploy using **Actions → CI → Run
workflow → main**. The secret is optional: without it, visitors can still
provide their own key.

Enable **Fonts Developer API** in Google Cloud Console and restrict the key to
that API. Under **Application restrictions → Websites**, allow
`https://heyportal.github.io/*` for the canonical Pages site, or your own
deployment hostname. Allow the origin rather than only `/open-scrl/*`, since
cross-origin browser requests can omit the path from their referrer. Add your
development origins only if the same key is also used locally. The Actions
secret keeps the value out of Git and workflow logs; Vite embeds it into the
public JavaScript, so website and API restrictions remain necessary.

See [custom fonts](custom-fonts.md) for local setup, key restrictions, and offline
font storage. Fonts, projects and media remain local; catalog and chosen font
downloads require an internet connection.
